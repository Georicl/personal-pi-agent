# 对话迁移摘要

## 背景

用户希望以 Pi Agent 为基底，构建一个深度符合个人电脑使用方式和个人工作流的 Agent，而不是一个只针对某个专业领域的机器人。

## 已形成的判断

- Pi-gui 是界面，不是 Pi Agent Runtime 本身。
- 可以保留 Pi 的 CLI、SDK、会话、工具和扩展机制，自己构建网页或桌面工作台。
- 个人知识库应当是长期知识来源，但 Pi 应通过检索、引用和更新工具使用它，而不是每次把全部知识注入上下文。
- Pi 原生能力适合承担代码工具、会话保存、会话分支、上下文压缩和基础 Agent 循环。
- Skills 适合描述代码、论文阅读、学术研究、知识整理和报告生成等工作方法。
- Extensions 适合提供知识库搜索、笔记写入、项目注册、任务状态、浏览器和外部服务等动作。

## 目标能力

1. 代码编写、阅读、调试和测试。
2. 本地资料和论文阅读。
3. 个人知识库的检索、整理、添加和维护。
4. 网络搜索和网页内容提取。
5. 格式化的学术研究流程，包括来源、证据和引用。
6. 生成报告、计划并执行下一步任务。
7. 浏览器操作，包括打开、点击、填写、上传和下载。
8. 使用 Pi 原生的会话恢复、分支、上下文压缩等能力。

## 建议架构

```text
Web UI
  ↓
Local Node/TypeScript Service
  ↓
Pi SDK / AgentSession
  ↓
Skills + Extensions + Tools
  ↓
Knowledge Base / Projects / Browser / External Services
```

## 下一步建议

先实现一条最小闭环：选择项目或 Global Chat → 创建或恢复会话 → 输入任务 → 流式显示 Agent 事件 → 更新任务状态 → 显示结果和文件 diff。
